What this generator does

This tool produces cryptographically random passwords and passphrases inside your browser. It uses the Web Crypto API that every modern browser ships, draws randomness from the operating system's cryptographically secure random number generator, and assembles the password from the character sets or word lists you select. Nothing is transmitted to a server, nothing is stored, and nothing is logged. If you want to verify the claim, load the page, disable your network connection, and press Generate. The tool continues to work because it does not need a server.

Two modes are supported. In password mode, the tool draws characters from the pools you enable, at the length you choose. In passphrase mode, it draws words from a fixed list and joins them into a readable phrase in the style popularised by the diceware method and the EFF wordlist. Both modes report an entropy estimate so you can compare settings against the strength you actually need.

If the AI insight button is pressed, only anonymous metadata is sent to a small serverless function that runs once and then stops. The mode, the length, the pool size, and the entropy estimate are shared. The password characters themselves are never included in that request, and neither is anything you typed into the password manager of your browser.

How entropy works

Entropy is a measure of unpredictability, expressed in bits. Every additional bit doubles the number of equally likely candidates an attacker has to try. A password with one hundred bits of entropy has two to the power of one hundred possible values, which is far beyond anything a realistic attack can enumerate. The formula for character-based passwords is simple.

Entropy (bits) = Length × log₂(Pool size)

If the pool is ninety-four characters, which is what you get when uppercase letters, lowercase letters, digits, and the common symbols are all included, then log₂(94) is about 6.55 bits per character. A sixteen-character password from that pool has about 105 bits of entropy. A twelve-character password from the same pool has about 78 bits. Doubling the length doubles the entropy; adding ten characters to the pool only adds about half a bit per character, which is why length dominates the calculation.

Passphrase entropy works differently. If the word list contains 7,776 words and every word is drawn independently, each word adds about 12.9 bits. A five-word phrase has about 64 bits, a six-word phrase has about 77 bits, and a seven-word phrase has about 90 bits. Those numbers are conservative because they assume the attacker knows the wordlist and the length, which is the correct assumption for any well-designed phrase generator.

A useful reference point. Sixty bits is enough for accounts that a determined attacker has no reason to target. Eighty bits is a reasonable target for an account tied to your identity, such as email or a bank login. One hundred bits and above is appropriate for an encryption key, a master password for a password manager, or a full-disk encryption passphrase.

Password length and character sets

Length is the single most important knob on the generator. Every extra character multiplies the number of possible values, and the effect compounds. A twelve-character password is exponentially weaker than a twenty-character password from the same pool, even though the two strings look similar. If a service lets you pick the length, pick the longest one it accepts and do not worry about memorising it, because a password manager can store it for you.

Character sets are the second knob. Each set you add expands the pool, which raises entropy at a given length. The full ninety-four-character set is uppercase, lowercase, digits, and the common symbols. Some services reject certain symbols, and some reject symbols entirely, in which case the honest answer is to generate a longer password rather than to edit a strong one into a predictable pattern. Editing a strong password by hand usually introduces structure that an attacker can model, which removes most of the benefit of the randomness in the first place.

The exclude-ambiguous option removes characters that look alike in many fonts, including zero and capital O, lowercase l and the digit one, and capital I and lowercase l. Excluding them makes the password easier to read aloud and to type by hand from a printed sheet or a second screen. The trade-off is a slightly smaller pool, which is easy to compensate for by adding one or two characters to the length.

Passphrases and when to use them

A passphrase is a sequence of random words joined into a readable string, such as sunny-harbour-basket-copper-mint. The idea is simple: humans remember words better than they remember random characters, so a long phrase made of random words is both easier to remember and harder to guess than a short string of random characters. The method traces back to the diceware approach, which uses physical dice to pick each word from a numbered list, and it is the recommended technique in most modern guidance for any password that has to be remembered rather than pasted.

Three practical rules make a passphrase strong. First, the words must be drawn at random from a large list, not chosen by you. A phrase made of words you liked is easier to guess than its length suggests, because the pool the attacker has to consider is much smaller than the official list size. Second, the phrase should be long enough. Five words is the practical minimum and six or seven is better for anything important. Third, the phrase should be unique. Do not reuse the same passphrase across accounts, for the same reason you would not reuse a password.

The generator draws from a fixed list of common English words that is included in the page, and it lets you choose the word count, whether to capitalise each word, whether to append a random number, and whether to join the words with hyphens. The hyphen option makes the phrase easier to read and to type, and the capitalisation option does the same at the cost of a very small amount of entropy, which the length more than compensates for. If you are generating a passphrase for someone who has to type it on a phone, the hyphen and capitalisation options are worth leaving on.

The case against password reuse

Reusing passwords is the most common single reason accounts get compromised. When a service suffers a data breach, the attacker usually gets a list of email addresses and password hashes, and if the hashing is weak, the plaintext passwords can often be recovered in bulk. Those pairs are then tested against other popular services in automated credential-stuffing attacks, which run twenty-four hours a day and require no particular skill to operate. A breach at a shopping site you visited once can hand an attacker the password to your email account, your bank, and your social profiles, if all of them share the same password.

The fix is a password manager, and the fix for the password manager is one strong password you do actually remember. Use this generator to create a unique password for every service you care about, store them in a password manager, and let the manager handle the remembering. The single password or passphrase that unlocks the manager is the only one you need to memorise, and this generator can produce that too, ideally in passphrase mode with a word count of six or more.

Storing and sharing safely

A strong password is only one part of account security. Multi-factor authentication, usually a time-based code from an authenticator app or a hardware key, is the second part and is worth enabling everywhere it is offered. A password manager is the third part, because it prevents the reuse that undermines the first two. Together, those three habits cover the vast majority of realistic account takeover scenarios.

Never send a password through a channel you would not want a third party to read. Email, SMS, and most chat applications are not end-to-end encrypted, and even when they are, the recipient's device may be compromised. If you must share a password with a colleague, use a password manager's built-in sharing feature, or send it through a channel that both of you control, and change it after the collaboration ends. If you suspect a password has leaked, change it immediately and enable multi-factor authentication if you have not already.

What the strength meter means

The strength meter estimates entropy from the pool size and the length, and it maps that estimate into five labels. The mapping is a rule of thumb, not a guarantee against every attack.

Good60 to 79 bitsReasonable for general use
Strong80 to 99 bitsRecommended for most online accounts, including email
Very Strong100 bits and aboveSuitable for master passwords, encryption keys, and high-value accounts

Entropy is not the only thing that matters. A password can be exposed through phishing, through a compromised device, through a data breach at the service that holds it, or through accidental sharing, no matter how many bits it has. The strength meter tells you how hard the password would be to guess from scratch; it does not protect against any of the other failure modes, and it should not be read as a guarantee that the account is safe.

Common mistakes

Editing a strong password into a memorable one. If you take a random string and change a few characters so you can remember it, you have removed most of the randomness. The result is usually far weaker than it looks. Generate a new password with the settings you actually want, and let a password manager store it.

Using the same password everywhere. The strength of an individual password does not matter much if the same one is used on a hundred services, because the weakest service in the set determines the security of the whole set. Unique passwords, one per account, stored in a manager, is the correct approach.

Choosing a short password because it looks random enough. Twelve random characters is weaker than sixteen, and sixteen is weaker than twenty-four. Length dominates the calculation, and the strongest choice that a service accepts is almost always the right one.

Disabling symbols on a service that accepts them. Adding symbols expands the pool, which increases entropy at a given length. If the service accepts them, include them. If it does not, add length instead of giving up.

Storing the password in a screenshot, a note, or a browser tab that stays open. The generated password is on screen until you close the tab. If you need to keep it, put it in a password manager immediately, and clear the page when you are done.

Sharing a password through email. Email is not a secure channel. If a password has to move between two people, use a password manager's sharing feature or a channel both parties control, and change the password after the collaboration ends.

Assuming MFA makes a weak password safe. Multi-factor authentication reduces the risk from a stolen password, but it does not eliminate it. Phishing kits that relay MFA codes are common, and account recovery flows often bypass MFA entirely. Use a strong unique password and MFA together.

Where this tool stops

This generator produces random strings and passphrases in your browser. It does not store them, does not synchronise them between devices, and does not audit the security of the sites you use them on. It does not check whether a password has appeared in a known breach, does not detect phishing pages that try to collect what you paste, and does not replace a password manager. Those responsibilities belong to the user and to the tools that handle storage and account security.

It also does not provide legal or professional advice on security compliance. Decisions about which standard to follow, which length to require, and which authentication factors to accept depend on the organisation, the industry, and the applicable regulations. The tool produces strong random output; the policy that determines how strong it needs to be belongs somewhere else.

What the tool does give you is a fast, transparent, private way to generate a password or passphrase that is genuinely random, with an honest estimate of its entropy and a clear statement of its limits. Used together with a password manager, multi-factor authentication, and the discipline of one password per account, it is a practical starting point for improving the security of everything you log into.

Frequently asked questions

Is this password generator safe to use?

Yes. The generator uses the Web Crypto API that every modern browser ships, which draws randomness from the operating system's cryptographically secure random number generator. The passwords are built inside your browser tab and are never sent to any server. No account is required, no password is logged, and no password is stored. You can verify the claim by loading the page, disabling your network connection, and generating a password; the tool continues to work because it does not need a server.

How long should a password be?

NIST's current guidance recommends a minimum of 8 characters and encourages longer passwords, while most security teams now suggest 16 characters or more for anything that matters. The reason is that length increases the number of possible combinations exponentially. A 16-character password drawn from the full ninety-four-character printable ASCII set has about 104 bits of entropy, which is far beyond the reach of any realistic brute-force attack. For an encryption key or a master password, aim for 20 characters or more, or use the passphrase mode to generate a long diceware-style phrase.

What is entropy and why does it matter?

Entropy is a measure of how unpredictable a password is, expressed in bits. It is calculated as the password length multiplied by the base-two logarithm of the size of the character pool. A password with high entropy has many equally likely possible values, so a guessing attack has to try an enormous number of candidates before it succeeds. A password with low entropy has few possible values and can be cracked quickly. The strength meter in this tool estimates entropy from the selected pool and the chosen length and labels the result Weak, Fair, Good, Strong, or Very Strong.

Should I include symbols and numbers?

Symbols and numbers increase the size of the character pool, which raises entropy at a given length. They are not strictly necessary if the password is long enough. A 24-character lowercase-only password has about 113 bits of entropy, which is stronger than a 12-character mixed-case password with 79 bits. The practical recommendation is to include every character type the service accepts and then make the password as long as the service allows. If a site rejects symbols, do not edit a strong password into a predictable pattern; generate a new one with the character sets that the site actually accepts.

What does exclude ambiguous characters mean?

Some characters look almost identical in many fonts, especially zero and capital O, lowercase l and the digit one, and capital I and lowercase l. Excluding the ambiguous set removes those characters from the pool. That makes the password easier to read aloud, to type from a printed sheet, or to copy by hand from a phone screen to another device. It slightly reduces the pool size and therefore the entropy per character, which you can compensate for by adding one or two characters to the length.

Should I use a passphrase instead of a password?

Passphrases are long sequences of random words, in the style popularised by the diceware method and the EFF wordlist. They are easier to remember than random character strings of the same strength and easier to type accurately on a phone. A five-word passphrase drawn from a list of 7,776 words has about 64 bits of entropy, and a six-word phrase has about 77 bits. That is comparable to a strong mixed-character password and often easier for a human to use. This tool supports both modes so you can pick the one that fits the account.

Why should I avoid reusing passwords?

Password reuse is the single most common reason accounts get compromised. When a service you use suffers a data breach, the email and password pairs are often published or sold, and attackers immediately test the same pairs against other popular services in automated credential-stuffing attacks. If you use the same password on your email and on a shopping site, a breach at the shopping site can lead to a takeover of your email. Using this generator to create a unique password for every service, stored in a reputable password manager, is the most effective single improvement you can make to your account security.

Does this tool store the passwords I generate?

No. Passwords are generated in the page using the browser's crypto.getRandomValues function and are never transmitted to any server. Nothing is written to localStorage, sessionStorage, cookies, or IndexedDB. The passwords disappear from memory when you close or reload the tab. If you press the AI insight button, only anonymous metadata is sent, meaning the mode, the length, the character pool size, and the entropy estimate. The password characters themselves are never included in that request.

Can I use this generator offline?

Yes, once the page has finished loading. The generator does not call any server, and the Web Crypto API is part of the browser itself. If you save the page to your device with the browser's Save Page As option, the tool continues to work without a network connection. That makes it usable on an air-gapped machine, on a phone in airplane mode, or anywhere else where you would rather not be online while generating a password.

What is the modulo bias problem and does this tool avoid it?

When you map a random integer into a range that is not a power of two using the modulo operator, some values become slightly more likely than others. The bias is small, but a careful generator avoids it. This tool uses rejection sampling, which draws a fresh random value whenever the first value falls in the biased tail of the range. The result is a uniform distribution across the entire character set, which is what the entropy calculation assumes. Most users will never notice the difference, but the practice is the correct one for a security tool.
